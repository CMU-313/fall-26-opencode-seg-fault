## Property test design

The six properties are implemented in [learning-mode.property.test.ts](../packages/opencode/test/session/learning-mode.property.test.ts), with a shared [test fixture](../packages/opencode/test/session/learning-mode.fixture.ts). They cover four kinds: invariant, metamorphic, model / oracle and round-trip. Each property has a comment naming its requirement and kind.

The tests run real OpenCode server processes against a local test model server. They inspect the actual provider requests, persisted session messages, config-file bytes and terminal logs. Only model responses are simulated; config loading, request assembly, session persistence and logging use the production implementation. Each generated case has isolated project directories, user configuration and a persistent test database. R4 and R5 use separate processes to check process-local overrides and restart behavior.

Generators vary the model, read/glob tool settings, other project instructions and one to three conversation turns. Questions include loop boundaries, quotes, multiline code and Unicode. R3 checks both conflicting config pairs for every generated request context. R4 generates numeric and textual boolean aliases, mixed case, surrounding whitespace, and valid config files both with and without `$schema`. It also always replays the schema-less counterexample and a padded `" TRUE "` override as explicit fast-check examples; both override directions are therefore exercised in every run. R7 generates common typos and other non-empty invalid values, and checks enabled, disabled and unset project settings. Generator comments in the test file explain these choices.

## Step 3: R4 triage and fix

The initial shrunk counterexample used `OPENCODE_LEARNING_MODE=false`, global `learning_mode: false`, project `learning_mode: true`, and files without `$schema`. The loader added `$schema`, so the old byte-preservation assertion failed. This is a **requirement conflict**, not evidence that the environment override was saved. The existing [config loader](../packages/opencode/src/config/config.ts) initializes missing schema metadata, and the existing `preserves env variables when adding $schema to config` test in [config.test.ts](../packages/opencode/test/config/config.test.ts) explicitly protects that behavior. The R4 revision above allows this initialization. Its property still generates schema-less files, checks that all saved settings remain unchanged, and compares exact file bytes after initialization. Already initialized files must retain their exact bytes from the start.

There was also a **code bug**: [Flag.OPENCODE_LEARNING_MODE](../packages/core/src/flag/flag.ts) lowercased the value without trimming it, so a recognized value such as `" TRUE "` fell back to the file setting. The parser now trims before lowercasing. Five focused config cases cover padded textual/numeric true and false values, tabs/newlines, and a whitespace-only value. The property retains generated whitespace variants and explicitly replays a padded true override against a false project setting.
